# ADR-0003: 存档使用版本化 JSON,禁止 Resource 序列化到 user://

> status: accepted | 日期: 2026-07-04

## 背景

Godot 提供 `ResourceSaver` 直接把 Resource 存到 `user://`,看起来最省事,但有两个致命问题:(1) `.tres/.res` 可嵌入脚本,从用户可写目录加载等于给玩家开代码注入后门;(2) 字段增删改后旧档反序列化行为脆弱,无法控制迁移。

## 决策

玩家存档一律使用 `{ "version": N, "data": {...} }` 结构的 JSON。`SaveService` 从第一天起维护迁移表 `{1: _migrate_1_to_2, 2: _migrate_2_to_3, ...}`,加载时逐级升级。

## 考虑过的替代方案

- **ResourceSaver 存 .tres**:安全隐患 + 版本脆弱,弃用。
- **二进制自定义格式**:防篡改更好,但调试成本高,前期不值,可作为上线后的加固项(JSON 外层加密/签名即可平滑过渡)。

## 后果

- 正面:存档可读可 diff,方便调试与客服排查;版本迁移路径明确。
- 负面:存/读需要手写字段映射,接受。
- 新约束:静态配置仍然用 `.tres`(只读、随包分发,不受此限);`user://` 下只允许出现 JSON。
