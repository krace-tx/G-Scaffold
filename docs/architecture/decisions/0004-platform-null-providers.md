# ADR-0004: 平台能力一律经防腐层访问,并提供 Null 实现

> status: accepted | 日期: 2026-07-04

## 背景

广告、内购、统计、推送等第三方 SDK 是全项目变更最频繁的外部依赖(换 SDK、SDK 升级破坏 API)。业务代码直接调 SDK 会把这种不稳定扩散到全项目。同时,SDK 只在真机可用,若无替身实现,编辑器里无法跑通"看广告→领奖"等核心流程,日常开发被迫依赖真机调试。

## 决策

每类平台能力定义 `@abstract` 契约(如 `AdProvider`),真实现按 `OS.get_name()` 由工厂选择;编辑器与不支持的平台一律注入 **Null 实现**(如 `NullAdProvider` 延迟 1 秒后自动发奖)。业务代码只认 `App.platform` 门面。

## 考虑过的替代方案

- **业务直接调 SDK 单例 + `if OS.get_name()` 分支**:平台判断散落全项目,换 SDK 等于全局重构,弃用。

## 后果

- 正面:F5 在编辑器跑通全流程;换 SDK 只改 `platform/` 内部;CI 可无头运行;SDK 初始化失败可降级为 Null,游戏照常可玩。
- 负面:每接一个 SDK 多写一个抽象层 + Null 实现,接受此成本。
- 新约束:`game/` 中出现任何 SDK 类名 / `Engine.get_singleton()` 调用即违规。
